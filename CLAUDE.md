# CLAUDE.md

Guidance for Claude (and other agents) working in this repository.

## What this is

**Arabic RTL for Claude** — an open-source Chrome/Chromium extension
(**Manifest V3, vanilla JS, no build step, no dependencies**) that makes
**Arabic** text display right-to-left in the Claude AI web app (`claude.ai`,
`claude.site`): responses, user messages, and the input box.

It is a trust-focused alternative to closed-source RTL extensions: everything
runs locally, the only permission is `storage`, and it makes **no network
requests**. Keep it that way.

## Hard rules

- **Scope: Arabic RTL.** The extension detects Arabic and displays it
  right-to-left. Keep new work consistent with that purpose.
- **No network, no tracking, no extra permissions.** `storage` is the only
  permission. Don't add `host_permissions`, analytics, remote fetches, or new
  permissions without a very good reason.
- **No dependencies / no build step.** Plain HTML/CSS/JS loaded directly by the
  browser. Don't introduce bundlers, frameworks, or npm runtime deps. (Node is
  used only for the dev-time test runner.)
- **License is MIT.** Don't reintroduce other licenses.
- **Don't copy the closed-source "RTL Responder" extension's code or name.**
  This is an independent, original implementation.

## Architecture (where things live)

```
manifest.json   MV3 config. content_scripts.js order matters:
                ["src/constants.js","src/detect.js","src/content.js"]
src/
  constants.js  self.RTL_CONFIG = { storageArea:"sync", defaults:{enabled,inputBoxEnabled,uiLang} }
                Loaded first in ALL three contexts (content/popup/worker) =
                single source of truth for settings.
  detect.js     self.RTL_DETECT = { detectDir }. Pure Arabic-direction logic,
                also CommonJS-exported so test/ can require it. UNIT-TESTED.
  content.js    The core. Scans the DOM, applies dir="rtl"/"ltr". See below.
  content.css   Alignment + isolates code/KaTeX as LTR inside RTL blocks.
  background.js  Service worker; seeds defaults on install. Uses
                importScripts("constants.js") (path is worker-relative → src/).
  popup.*       Toolbar popup: 2 toggles + interface language (ar/en).
icons/          PNGs generated by scripts/make_icons.py (pure Python, no deps).
test/           node:test suite (detection + manifest validation).
.github/workflows/ci.yml  runs `npm run check` + `npm test` on push/PR.
```

### How content.js works (the important part)

- Reads settings via `RTL_CONFIG`; detection via `RTL_DETECT.detectDir`.
- `detectDir(text)` → `"rtl"` | `"ltr"` | `null`. `null` = no Arabic → element
  is left untouched (we never force LTR on Claude's own content).
- Direction is set with the `dir` attribute; processed elements are marked with
  `data-rtl-dir` (content) / `data-rtl-input` (composer) so we can skip
  redundant writes and cleanly `revert()` on disable.
- A `MutationObserver` (`{childList, subtree, characterData}`, **not**
  `attributes` — that's what prevents an infinite loop) feeds a
  `requestAnimationFrame`-batched flush. Work is split:
  - `pendingTrees` (childList additions) → full subtree scan.
  - `pendingBlocks` (characterData / streaming tokens) → re-check just that
    block (no `querySelectorAll`). This keeps the streaming hot path cheap.
- `CONTENT_SELECTOR` is standard block tags **plus** one Claude-specific hook,
  `[class*='whitespace-pre-wrap']` (user-message bubbles). That class hook is
  the single most likely thing to break if Claude changes its markup — start
  there if RTL stops working.
- `SKIP_SELECTOR` (pre/code/katex/contenteditable/textarea/input) is never
  flipped; the composer/edit box are handled separately by `applyEditorDir`,
  gated on `inputBoxEnabled`.

## Conventions / gotchas

- `RTL_CONFIG` and `RTL_DETECT` are globals shared via `self.X = ...`. They work
  because all files in one `content_scripts` entry share an isolated world, the
  popup loads `constants.js`/`detect.js` before `popup.js`, and the worker
  `importScripts` them. If you add a new context, load the shared files first.
- `importScripts("constants.js")` in `background.js` is **worker-relative**
  (resolves to `src/constants.js`). Do NOT change it to `"src/constants.js"`.
- Keep `manifest.json` `description` ≤ 132 chars (a test enforces this).
- If you change settings keys/defaults, edit them **only** in `constants.js`.

## Developing & testing

No install needed (Node ≥ 18 for the built-in test runner):

```bash
npm run check   # node --check on all JS
npm test        # unit + manifest tests
npm run ci      # both (mirrors GitHub Actions)
npm run icons   # regenerate icons after a design change
npm run build   # package dist/arabic-rtl-for-claude-v<version>.zip for the Web Store
```

No build/transpile step exists or should be added — `npm run build` only zips the
runtime files. Bump `manifest.json` `version` before each store release.

Load it in the browser: `chrome://extensions` → Developer mode → **Load
unpacked** → select the repo root → **Reload** ↻ after edits.

When you add behavior, add or update a test under `test/` so CI guards it.
